Ny integrationsplatform som erstatning for BizTalk

Adaptere, porte, filudveksling og XML-transformation som kode med tests, i stedet for konfiguration i et designværktøj. Mønstret findes allerede i drift: WF Proxyen holder de gamle SOAP-kontrakter i luften med SoapCore og sender hver operation til det rigtige system bag facaden. Forslaget er at gøre det samme med BizTalk, én port ad gangen, og at lade den logik, der i dag ligger som C#-kode inde i BizTalk, leve som egne services.

Udgåendeorkestreringer på bts-01, som WF2 kalder synkront: Medlem, Virksomhed, Navnebase, SendOutput, UM, IIS m.fl.
Indgåendeforbrugere, der kalder WF via BizTalk: LivNet, IIS, Ekstern Portal, dele af HIP, GDPR-slettemotor
Filer & XMLfiludveksling over FTP/SFTP og XML-transformation håndteres i dag af BizTalk og skal med over, som kode
Uændretfor forbrugerne: SOAP-facaderne beholder WSDL, URL og header-konvention
API-gateway

Én indgang for synkrone kald

ASP.NET Core-host på IIS eller som Windows Service, som WF2 kører i dag. TLS, adgangspolitik og rate limits pr. rute, korrelations-id hele vejen igennem.

SOAP-facader

Strangler med SoapCore

Samme bibliotek og SOAP-plumbing som WF Proxyen. Eksisterende kontrakter serveres uændret og oversættes indadtil. Hver Ser*Url flyttes, når adapteren er klar. Rollback er en URL.

Adaptere, filer & XML

Porte og transformation som C#

Ét adapter-projekt pr. fagsystem: REST, SOAP og FTP/SFTP med kvittering og dubletkontrol. XML-transformation skrives som kode med fixture-tests. Kontrakt-tests seedes fra optaget BizTalk-trafik.

Egne services & messaging

Logikken ud af BizTalk

C#-koden fra orkestreringerne bliver selvstændige (mikro)services, der taler med platformen via API og en messaging service med rækkefølge pr. sag og genkørsel fra en konsol.

Kilder: IP.WF2.0 (ADR-002, ADR-005, wiki Integrationer), SoapCore/YARP-dokumentation. Detaljer i det fulde forslag IP After BizTalk. Intet er implementeret; BizTalk-artefakter skal afdækkes i en fælles forundersøgelse.
