# CRM/ERP E2E workflow

Run the existing serial Playwright suite against an isolated Development Aspire
demo on a disposable Ubuntu GitHub runner. Start with nightly and manual triggers;
required PR checks remain a later rollout decision after a clean hosted run.
Use the local Service Bus emulator and SQL Server, deterministic enrichment and a
fresh masked E2E key. No Azure or model credentials are required.

Capture the discovered test catalog before starting infrastructure. Always generate
an offline HTML result view from that catalog and the actual Playwright JSON report.
Show passed, failed, flaky, skipped and unexecuted tests separately. Missing results,
runner errors or incomplete coverage must fail validation. Keep the historical
coverage map as a clearly dated snapshot, linked separately from live results.

Upload the result view, Playwright HTML/JSON, failure evidence and bounded application
logs. Always attempt explicit AppHost shutdown. Restrict token permissions to read
repository contents and retain artifacts for 14 days. Do not change branch protection.
