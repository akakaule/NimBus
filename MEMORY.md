# Memory

- 2026-07-02: When Codex reports plugin load warnings from cached plugin files, validate the exact reported path and any mirrored marketplace source copy. Hook config JSON currently accepts only a top-level `hooks` field; do not add descriptive metadata there. For skill frontmatter descriptions containing quoted examples, use YAML-safe quoting and run the packaged `quick_validate.py` against the skill folder.
- 2026-07-06: For React effects keyed by route params, guard every async state commit with an effect-local `active` flag or monotonic ticket. This includes independent parallel fetches and follow-up enrichment requests, otherwise an older route can overwrite the currently displayed event after navigation.
- Worktree-scope correction: when the user asks for a new Git worktree, create and verify the isolated worktree before editing or dispatching implementers, and run all implementation and verification commands from that exact path.
- Authorization-cache correction: never promote a prior ACL snapshot into a generation created by explicit invalidation when reload fails. Reuse last-known-good only within the same generation; after invalidation, deny until a complete snapshot reload succeeds.
- AsyncAPI governance corrections: validate operation `messages` refs by accepting both generated channel-scoped refs and direct `#/components/messages/...` refs; diff enum sets recursively through array `items` so removed item enum values stay breaking.
- AsyncAPI exporter examples: convert object-map payloads (`JObject`, `IDictionary`, and `IReadOnlyDictionary`) before the generic `IEnumerable` fallback so fluent examples export as JSON objects instead of arrays of entries.
- AsyncAPI merge conflict pattern: preserve independent extension inputs rather than choosing one side. When exporter code moves to `NimBus.ServiceBus.AsyncApi`, keep `NimBus.Core.Events.AsyncApiFormat` as the canonical SDK/provider type and use distinct aliases (`CoreAsyncApiFormat`, `ServiceBusAsyncApiExporter`) inside `NimBus.CommandLine` to avoid obsolete bridge type shadowing. Verify with CommandLine tests plus `dotnet build src/NimBus.sln`.
- Review correction pattern: before classifying surprising behavior as a defect, cross-check the relevant ADRs and spec decision/negative sections. Intentional compatibility trade-offs (for example ADR-012's handoff `ErrorType` wrapper) should be reported as accepted design debt, not bugs, unless the requested scope explicitly reopens the decision.
- Cross-surface status contracts: derive API/service eligibility from the authoritative enum plus documented CLI rules, not from a UI option list. A UI may intentionally expose only a common subset; do not silently narrow the backend contract to match it.
- Cancellation/checkpoint correction: when a cancellation handler retries durable bookkeeping, define and enforce an idempotent provider contract that preserves the first committed timestamp, and test both zero-commit and partial-commit cancellation. For async cleanup APIs without cancellation-token support, initiate cleanup, bound the wait with the host token, and observe eventual completion so shutdown cannot hang or leak task failures.
- Regression-review pattern: metadata getters that lazily parse untrusted bodies must memoize both successful and failed attempts, return a safe missing value on parse failure, and keep normalization in one owning layer so lifecycle and dead-letter paths cannot throw. Cleanup guards must cover recovery as well as shutdown; best-effort cancellation bookkeeping needs a bounded wait, the actual failure in diagnostics, and an always-running provider conformance test. Centralize provider logging before exception scrubbing, expose only safe status/retry fields, and make scoped APIs fail closed when no scope factory exists.
- Orchestration documentation correction: strict workflow correlation, message identity, and lineage cannot use `PublisherClient.Schedule(IEvent, ...)`, which generates native metadata and exposes no overrides. Use the intended decorated `ISender` with a validated prebuilt `IMessage`, guard against `TryAddSingleton<ISender>` shadowing, and never conflate topology-assigned `EventId` with durable timeout/workflow identity. Distinguish direct broker cancellation from outbox logical cancellation, and keep ADR examples aligned with SQL/Cosmos atomicity limits.
- Inbox placement correction: verify the real settlement boundary before implementing record-on-success as a generic message-pipeline post-step. In NimBus, the pipeline terminal includes Resolver response publication and broker completion, so a store write after `next` is too late to fail safe. Decorate `IEventContextHandler` instead so check, handler execution, and inbox recording all finish before response/settlement, then bridge duplicate skips back to `StrictMessageHandler` with an explicit outcome.
- DI idempotency correction: when a registration uses `TryAdd*` for the effective service factory, optional sidecars (decorators, hosted services, notifiers) must be gated by the same first-registration ownership. A later benign duplicate registration must not partially enable sidecars that its discarded factory never uses.
- Test-fixture compatibility correction: do not add a same-arity overload whose reference-typed parameters overlap an existing nullable overload; existing `new Fixture(null, null)` calls become ambiguous. Use a clearly named static factory for optional decorator/test modes.
- Provider-contract correction: match approved public type names and the complete storage DDL, including defaults and indexes, rather than implementing only behaviorally equivalent shorthand. When live provider credentials are optional, run the shared conformance contract unconditionally against the real provider implementation through a faithful fake adapter, and retain the credential-gated live suite as additional proof.
- Frontend verification correction: under Node 22, the full Vitest suite needs a process-local `--localstorage-file` setting or the unrelated application-shell theme test sees an undefined global `localStorage`. Configure a temporary file for the test process; do not change application code to accommodate the runner.
- Public-adapter compatibility correction: when adding cancellation support, preserve the provider's existing overload shape, including request-options parameters. A new same-arity overload that substitutes `CancellationToken` can make existing calls with a literal `default` argument source-ambiguous.
- Telemetry-contract correction: audit an instrument's description against every producer, including background cleanup paths, so published metadata does not describe only a subset of the measurements it receives.
- MSTest analyzer correction: this repository treats `DataTestMethod` as obsolete (`MSTEST0044`); parameterized tests must use `TestMethod` with `DataRow`. Reuse a `static readonly` expected array when passing it to `CollectionAssert` so new tests do not introduce `CA1861` warnings.
- Principal-authentication correction: checking only that `ClaimsPrincipal.Identity` exists is not fail-closed; an unauthenticated `ClaimsIdentity` can still carry forged group/email claims. Require `Identity.IsAuthenticated == true` before resolving compatibility or stored ACL grants, and test both forged marker and matching-email principals.
- Generated-enum request correction: a required non-nullable enum generated from OpenAPI can silently default an omitted JSON property to its zero member because MVC uses System.Text.Json while required metadata may be Newtonsoft-only. Initialize the partial DTO to an invalid sentinel and validate the allowed enum set at the privileged boundary, with raw-HTTP omission and unknown numeric/string tests.
- Single-flight cache correction: wrapping a side-effecting `ConcurrentDictionary.GetOrAdd` value in `Lazy<T>` prevents duplicate creation, but `Lazy<T>` also caches transient exceptions. On failure, conditionally remove that exact key/value pair before rethrowing so later calls can retry without deleting a concurrent replacement.
- Scheduled-redelivery correction: preserve all valid broker/application properties, but do not reassign an absent partition key after setting a session id. Keep only the scheduling call inside the unsupported-scheduling exception translation; completion failures after a successful schedule must retain their original semantics.
- Async test-context correction: `HttpContextAccessor` stores context in `AsyncLocal`; assigning it inside an awaited fixture factory can be unwound when the factory returns. Use a direct `IHttpContextAccessor` test double when the context must remain stable outside that async helper.
- Security-audit scope correction: before claiming a configuration file ships or is committed, verify it with `git ls-files`/`git ls-tree` and `git check-ignore`, not filesystem presence alone. In particular, a local ignored `appsettings.Development.json` may enable dangerous development flags without being part of any release; report the local operational risk separately from repository advisory impact.
- Least-privilege review correction: trace exceptional and recovery paths before reducing a runtime identity to Receiver-only. The Resolver normally receives, but scheduled-redelivery during storage throttling also sends to its topic; preserve that entity-scoped Sender grant while removing namespace-wide Owner.
- Sensitive-identifier correction: do not call masking an identifier non-breaking until every route, lookup, settlement action, UI link, telemetry tag, and storage key has been traced. `SessionId` is both observable data and an operational identity in NimBus; protecting sensitive natural session keys needs opaque/HMAC identifiers or a coordinated contract/storage migration, not a simple response placeholder.
- Security-advisory metadata correction: derive the introduced version from the first release containing the complete exploitable chain, not merely the earliest appearance of one primitive. Verify that a named package is actually published and packable before assigning a NuGet ecosystem/product; the Resolver is deployed as an application, not published as `Akaule.NimBus.Resolver`.
- Message-authorization correction: an allowlist of valid endpoint names is not authorization when an attacker may select a different valid endpoint. Bind routing fields such as `ReplyTo` and manager-origin markers to broker-authenticated source identity or a signed capability, then test direct broker sends as the hostile path.
- GitHub-advisory API correction: repository security advisories must retain at least one vulnerability entry even when a false-positive draft is being corrected and closed. Represent “no released version affected” with an explicit pre-release-only range, update the disposition text, then close the draft; do not try to clear the vulnerabilities array.
- Frontend assertion correction: this repository's Vitest setup does not install jest-dom matchers. Use built-in assertions such as `toBeDefined()` and `toBeNull()` for Testing Library results instead of `toBeInTheDocument()`.
- Frontend query correction: list filter options often duplicate values rendered in the results. Scope Testing Library text queries to the semantic table or row with `within(...)` so assertions prove the result cell, not an identically named `<option>`.
- Event-type details correction: do not expose the catalog's `codeRepoLink` as a "View Source" header action. The API field may remain for compatibility, but the management page should focus on topology, schema properties, and the example payload.
- Durable-emulator test isolation correction: every spawned emulator test process must receive a unique `NIMBUS_SBEMULATOR_TOPOLOGY_PATH` and delete only that validated temporary directory on teardown. A shared default journal leaks topology across tests and can turn SDK admin retries or duplicate-entity checks into misleading flakes.
- WebApp PR presentation rule: whenever a pull request changes the WebApp's design or layout, or adds a new WebApp feature, capture a representative screenshot of the finished UI and include it in the pull request description.
- Refactoring-plan correction: inventory actual dependencies, existing extraction seams, current test doubles, and already-completed structure before claiming scope or benefit. Delete dead dependencies instead of narrowing them, retain shared conformance-tested fakes instead of multiplying bespoke doubles, verify runner configuration before prescribing workarounds, and make high-risk decomposition conditional when helper extraction may deliver the value without moving load-bearing orchestration.
- Plan-location correction: when the user explicitly chooses a documentation path or says not to use a methodology/skill, keep the plans at that exact path and do not relocate them to a framework-specific convention based on reviewer preference.
- Storage-dependency correction: verify plan inventories against every partial class before deleting a dependency. AdminService's partials still use message-tracking operations, so narrow its aggregate dependency to IMessageTrackingStore rather than removing it.
