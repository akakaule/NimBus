# CRM/ERP E2E implementation plan

1. Inspect existing demo contracts, fixtures, and transport/runtime availability.
2. Add failing tests for opt-in control guards and deterministic session scripts.
3. Implement bounded, authenticated Development-only controls and typed handler
   decoration, middleware probes, retry/classifier configuration, and job release.
4. Extend REST helpers and fixtures; update browser actions and deterministic
   handoff tests. Add bidirectional CRUD, ordered recovery, outcome classification,
   handoff edges, deduplication, and operational scenarios.
5. Add scoped raw-message probes and infrastructure scenarios where required;
   preserve test-owned state and document genuine demo capability limitations.
6. Compile affected projects, typecheck and enumerate tests, then run live E2E
   tests. Debug failures from logs and traces, rerun affected cases, and summarize
   verified coverage with remaining limitations.

Implementation is authorized by the user's request. No push or PR.

## Implementation evidence

The suite now contains 84 cases across 19 specs. Session-scoped controls are gated
by Development, the explicit profile flag, and an ephemeral key. Real API writes,
broker delivery, SQL outbox state, Resolver history, business audits and browser
operator actions provide the test oracles.

Live failures exposed five defects corrected alongside their coverage:

- Worker session dead-lettering passed a null properties dictionary to the Azure
  SDK; a real AMQP regression failed before the fix and passed afterward.
- ERP Functions needed explicit manual completion on its main trigger for
  transient failures to remain unsettled and redeliver.
- Resubmitting a failed CloudEvent handoff lost its parked event JSON; a WebApp
  regression failed before the fallback and passed afterward.
- Ordinary handler failures reached the Resolver but bypassed lifecycle failure
  notifications; a core regression failed before the catch-path fix and passed
  afterward.
- Session-lock loss after handoff unblock but before deferred scheduling stranded
  siblings on redelivery. Duplicate completion now resumes the drain only when
  no newer event owns the block. A two-row regression proved both recovery and
  preservation of a newer blocker; all 73 related core tests pass. Resending
  completion to the actual stalled live session moved its remaining sibling
  from Deferred to Completed immediately after the fix.

The initial complete live run passed 77/84. All seven failures subsequently passed
in a focused run. The outbox check was then strengthened to require a real
session-correlated dispatcher rejection before recovery; both outbox tests pass.
The combined run passed 83/84 and exposed the lock-loss defect above. The affected
handoff families were rerun after its repair. Results are recorded in the E2E README.
