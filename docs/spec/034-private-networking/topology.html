Spec 034 · proposed infrastructure

NimBus in a private network

What a NimBus deployment looks like once it runs entirely inside the customer's virtual network: every service reached through a private endpoint, every outbound call through the customer's firewall, nothing answering the public internet.

  • 1 hard blocker — Service Bus must move from Standard to Premium
  • 3 subnets supplied by the customer
  • 6–10 private endpoints
  • Opt-in — public mode stays the default

Topology

Switching an existing deployment

Existing deployments move in two passes so nothing is locked before the apps can reach it privately. The CLI records the intended state as a resource-group tag and converges to it on every run.

Order inside every deployment, enforced with Bicep dependsOn:

  1. DNS zones and VNet links (create mode)
  2. Service Bus, store and storage with the state's access settings
  3. Private endpoints and zone groups
  4. App VNet integration and routing: no app restarts into a network where its dependencies don't resolve
