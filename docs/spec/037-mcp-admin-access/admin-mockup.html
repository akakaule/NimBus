    Design notes: Admin → MCP access

    The full design is in Spec 037. These notes summarize it.

    1 · Two layers

    The deployment remains the trust anchor and the ceiling: NimBus__Mcp__Enabled, the Entra tenant, the client ID, the App ID URI, browser origins and the rate-limit maxima. The Admin tab holds a live policy that can only narrow that ceiling. Effective access = deployment ceiling ∧ admin policy ∧ Entra scope or app role ∧ NimBus role ∧ message state. A stolen Owner session can turn things off or restrict them, but it can't make NimBus trust another tenant.

    2 · Live, no restart

    Unlike Failure intelligence, which needs a restart because it changes provider wiring, nothing here changes DI. /mcp is mapped whenever the deployment allows it. A per-request gate in McpRequestGuardMiddleware and a tool filter read a 30-second cached policy. This is the AuditSettingsProvider pattern: a save refreshes this instance at once, and other instances catch up within the TTL.

    3 · Fail closed, stay compatible

    • No saved record means today's behaviour: everything the deployment allows is on. Upgrading changes nothing.
    • A store read that fails keeps the last known good policy. Until the first successful read, /mcp answers 503 [Unavailable]. It never falls back to the defaults, which may be wider than the saved policy. This is the opposite of audit settings, which fail open.
    • Turn off now is a separate POST that ignores the revision check, because an emergency stop must never fail with a 409. A normal save uses the revision check and answers 409 to a stale editor.

    5 · Storage and API

    • McpAccessSettings singleton on IEndpointMetadataStore, like AuditSettings and HeartbeatSettings: a Cosmos fixed-id document, a SQL migration and the in-memory store, plus conformance tests (defaults, round trip, revision conflict).
    • GET/PUT /api/admin/mcp/settings, POST /api/admin/mcp/turn-off and GET /api/admin/mcp/activity, defined in api-spec.yaml (NSwag). Site Owner only, CSRF header, bounded body.
    • New audit type UpdateMcpSettings, always recorded, with the diff in the audit data.

    6 · Suggested slices

    • A: activation switch, Turn off now, per-action and payload switches, effective-access preview, connect panel. This covers "enable and configure MCP usage".
    • B: recent activity, people allowlist, client allowlist with refused-client suggestions.
    • C: endpoint visibility and write scope, lower-only limits.
    • Deferred: a daily change budget per caller. Audit rows record the display name, which isn't unique. It waits for Phase 2b's operation journal.
