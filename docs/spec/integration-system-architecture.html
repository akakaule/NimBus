    04 / Durable boundaries

    One session gate. Explicit handoffs.

    NimBus owns the session

    • Scope: tenant when applicable + integration endpoint + business session key.
    • At most one admitted head for a lane. A failed or externally pending head keeps later work blocked.
    • Recovery commands identify the original message and expected state. Repeated or stale commands cannot clear a later failure.
    • Admission pause affects new work. It does not cancel already-running activities or remote calls.

    The workflow engine owns progress

    • Durable steps, waits and timers stay in the engine’s own persistence.
    • A bridge records a stable run identity and start intent before attempting engine start.
    • Handoff-established state and early completion are reconciled before terminal settlement.
    • Active runs keep their release. A code or payload correction is an explicit, audited recovery decision.
    Admit message→Persist start intent→Start engine idempotently→Establish handoff→Reconcile completion

    A long-lived logical session block does not require holding a broker delivery lock for the duration of a workflow. Completion and callback commands use a control lane that remains runnable while business delivery is blocked.

    Failure example: the ERP created an order but the response was lost

    The worker records an ambiguous outcome and preserves the order’s session block. The operator sees the failed step and operation identity. A connector queries ERP by that identity. If the order exists, the integration records success and continues. If it does not, retry follows the target’s idempotency contract. If the outcome cannot be established safely, the run remains blocked for investigation. A blind retry is not evidence of correctness.

    Ordering example: REST and events update the same customer

    If both paths must serialize together, normalize them into the same integration endpoint and session scope. Separate endpoints do not automatically share a global lock. Agree a source/version sequence, gap policy and conflict rule if business order spans producers; SQL admission order by itself guarantees only the order in which the platform accepted work.

    Skip example: the failed business operation is intentionally abandoned

    A scoped, authorized skip records an incident reason and marks the original head skipped. Its successor can be admitted if the integration is not paused. The skipped operation is incomplete and remote effects are not automatically undone. Downstream consequences must be understood before a real operator issues this command.

    05 / Deployment & trust boundaries

    Run the platform close to your systems.

    Ingress boundary

    Expose contracts

    Publish only the required REST/callback routes through the organization’s ingress or API gateway. Connect to an existing identity provider. Give each partner contract-level permissions and request limits.

    SFTP intake can pull from an approved partner host or use an organization-managed landing server. The console is not a public partner portal.

    Private runtime

    Execute integrations

    Deploy API/intake workers, NimBus processing and integration workers as separately scalable services. Container or VM hosting is viable design scope; orchestrator selection is still open.

    Isolate adapters by credential and business trust boundary. Use SQL coordination for singleton pollers and session admission in the proposed on-prem profile.

    Private data & management

    Protect state and control

    Keep SQL Server, broker administration, workflow persistence and management APIs on private networks. Store large payloads durably by reference and retain immutable revisions.

    Use governed outbound connections to internal ERP/CRM and partner hosts. Restrict credentials to their bindings; audit payload access and recovery separately.

    The on-prem profile must qualify broker, SQL, payload-store and worker failover as a whole. Backups need compatible run state, bridge state and payload references. SQL Server is the confirmed baseline; engine choice, high-availability topology and any disconnected-install requirement remain to be validated.

    06 / Developer & coding-agent experience

    Ship an integration as a reviewed package.

    Confirmed direction: integrations are written primarily in C#; the web console monitors and manages them. Give an agent a bounded business contract and runnable fixtures. Keep connector plumbing, admission and operations behavior in platform packages.

    01

    Define the contract

    A team supplies OpenAPI/AsyncAPI or file schema, mapping rules, session key, idempotency policy, target behavior and example inputs/outcomes.

    Secrets are binding references. Synthetic fixtures include duplicates, invalid data and ambiguous remote results.

    02

    Implement in C#

    A coding agent starts from an integration template, uses typed connector activities and writes mapping and behavior tests. Long waits use the selected durable engine.

    A narrow task changes integration code and fixtures; adding an integration should not require editing the platform runtime.

    03

    Build, promote, operate

    CI runs contract/recovery checks, exports the catalog and produces an immutable worker image or package. Environment bindings are applied through deployment configuration.

    The console discovers the release and its operations metadata. Operators see the integration, release, steps, session and source correlation together.

    07 / What the implementation must prove

    Turn the mockup into testable behavior.

    Durable acceptance

    Crash after committing REST or file intake but before replying or publishing. Retrying the original identity must recover the same operation.

    Session isolation

    Fail A1 and queue A2. B continues. Recover A1 while B remains unchanged; repeat across keys sharing one broker partition.

    Workflow handoff

    Crash between engine start, handoff and completion. Send early/duplicate callbacks. One logical run and the correct session block survive.

    Safe remote effects

    Lose ERP responses and expire worker leases. Reconcile or fail closed when destination idempotency/fencing cannot prevent a duplicate effect.

    Operator controls

    Verify permissions and stale-command checks on the server. Pause admission, recover a head, then resume. Audit the exact affected run and reason.

    Repeatable delivery

    Have an agent implement a second integration from fixtures. Deploy a new release while an older run waits, then resume under its pinned version.

    The linked operator mockup demonstrates selected state transitions in memory. It does not prove distributed locks, persistence, transport behavior, authorization or production failover.
